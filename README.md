# pari-mixer-scraper

Веб-приложение, которое собирает данные по матчам турнира Dota 2 (по
умолчанию — PARI Mixer Cup, league_id `19924`,
https://www.dotabuff.com/esports/leagues/19924-pari-mixer-cup) в локальную
базу SQLite и показывает их в браузере: выбираешь команду — видишь ники
игроков и героев, на которых они играли.

## Источники данных

Прямой скрейпинг HTML dotabuff.com не используется — сайт закрыт Cloudflare
(JS-челлендж "Just a moment...") для любых автоматических запросов. Вместо
этого используются три источника, и роли у них разные:

1. **Steam Web API** (`IDOTA2Match_570/GetMatchHistory`) — официальный API
   Valve, тот же, что использует сама Dota 2 / Dota Plus. Самый дешёвый
   способ получить список матчей лиги: один запрос отдаёт до 100 матчей
   сразу вместе с составами и героями. Требует бесплатный ключ, см. ниже.
   Результат матча (кто победил) он **не отдаёт**.
2. **mixer-cup.gg (GraphQL)** — источник правды по всему, чего нет в Dota:
   названия команд, составы, MMR, **результаты** (WIN1/WIN2), замены,
   очередь. Дёшево, несколько запросов за цикл. Он же перечисляет `matchId`
   всех игр турнира — это запасной путь поиска матчей, если Steam недоступен.
3. **[OpenDota API](https://docs.opendota.com/)** — только детали по
   конкретному `match_id`: драфт (picks/bans), стороны, `radiant_win`.
   По одному запросу на матч, поэтому это самое узкое место.

**Если ключ Steam недоступен**, список матчей приходится собирать из
mixer-cup и добирать каждый матч из OpenDota — по запросу на матч. На
шаред-IP (например, на free-тарифе Render) это упирается в rate-limit.
Признак в логах: `MixerCup match seed` тянет сотни матчей вместо нуля.

> Диагностика ключа: Steam отвечает голым `403` на **любой** эндпоинт, если
> ключ отозван/протух — это выглядит как «Valve закрыл API», но это не так.
> Проверьте тем же ключом `ISteamUser/GetPlayerSummaries`: если и там `403` —
> дело в ключе. Запрос **без** ключа при этом даёт `400`, а несуществующий
> метод — `404`; если так, значит до Steam вы доходите.

Намеренно **не** используются (проверено на этой лиге):
`/leagues/{id}/matches` — пусто, лига tier `excluded`; `/teams/{id}` —
отдаёт `200` с пустым телом; `/proPlayers` — ~4.4 МБ ради ~2 совпадений
из 10 (микс — это не про-игроки, а имена и так есть в ростерах mixer-cup).

### Как получить Steam Web API ключ

1. Откройте https://steamcommunity.com/dev/apikey (нужен Steam-аккаунт).
2. Зарегистрируйте ключ (domain можно указать `localhost`).
3. Скопируйте `.env.example` в `.env` и впишите ключ туда — **не в чат и не
   в код**:

   ```
   cp .env.example .env
   # затем откройте .env и впишите STEAM_API_KEY=...
   ```

## Установка

```bash
cd pari-mixer-scraper
python -m venv .venv
.venv\Scripts\activate        # Windows
pip install -r requirements.txt
```

## Запуск веб-приложения

**Windows, без терминала:** дважды кликните [`start.bat`](start.bat) в папке
проекта — он запустит сервер и через пару секунд сам откроет
http://127.0.0.1:5000 в браузере. Чтобы остановить — закройте открывшееся
чёрное окно консоли или нажмите в нём Ctrl+C.

**Через терминал** (PowerShell/cmd/bash — если нужно видеть логи или
приложение уже не через `.venv\Scripts\activate`):

```powershell
cd pari-mixer-scraper
.venv\Scripts\python.exe app.py
```

Откройте http://127.0.0.1:5000 в браузере. Сбор данных запускается сам в
фоне (см. «Автообновление матчей» ниже) — прогресс виден в шапке страницы,
слева появляется список команд, по клику показываются игроки и герои.

Сбор идемпотентен: повторные запуски докачивают только новые матчи, старые
не перезапрашиваются. Останов сервера — Ctrl+C в терминале.

## Деплой в облако (чтобы другие люди могли зайти по ссылке)

Локальный запуск виден только на вашем компьютере. Чтобы дать доступ другим —
разверните на [Render](https://render.com) (бесплатный тариф, поддерживает
Python из коробки). Шаги с созданием аккаунтов должны быть сделаны вами лично
— агент не может создавать аккаунты или логиниться от вашего имени.

1. **Создайте репозиторий на GitHub** (если ещё нет аккаунта — зарегистрируйтесь
   на github.com) и запушьте туда код:
   ```bash
   cd pari-mixer-scraper
   git remote add origin https://github.com/<ваш-username>/<repo-name>.git
   git branch -M main
   git push -u origin main
   ```
2. **Зарегистрируйтесь на [render.com](https://render.com)** (можно через GitHub).
3. **New → Blueprint** → выберите ваш репозиторий. Render сам прочитает
   [`render.yaml`](render.yaml) из корня проекта и настроит сборку/запуск.
4. Render попросит ввести значение переменной `STEAM_API_KEY` — впишите свой
   ключ в его дашборде (не в код, не в репозиторий).
5. Дождитесь деплоя — Render даст постоянную ссылку вида
   `https://pari-mixer-scraper.onrender.com`, которую можно скидывать кому угодно.

**Важные особенности бесплатного тарифа Render:**
- Сервис "засыпает" после ~15 минут без запросов и просыпается по первому
  обращению (~30-60 сек на холодный старт) — это нормально для бесплатного
  тарифа, а не баг.
- Диск на бесплатном тарифе не постоянный: `tournament.db` может обнуляться
  при перезапуске/пробуждении. Приложение это обрабатывает само — при
  старте, если база пустая, автоматически запускается сбор данных в фоне
  (см. `_auto_collect_if_empty` в [app.py](app.py)), так что сайт сам
  восстанавливает данные за 1-3 минуты без ручных действий.
  (Пробовали переехать на хостед-БД Turso/libSQL для постоянного хранения —
  откатили: их Rust-драйвер блокирует GIL при сетевых запросах настолько,
  что всё приложение переставало отвечать на время сборки данных.)

## Автообновление матчей

Данные обновляются сами, без ручного управления, через два механизма:

1. **Фоновый таймер внутри приложения** — раз в `COLLECT_INTERVAL_SECONDS`
   (по умолчанию 600 сек = 10 мин) сам запускает сбор. Работает только пока
   процесс жив.
2. **[GitHub Actions](.github/workflows/keep-alive.yml)** — раз в ~10 минут
   дёргает `POST /api/collect` на задеплоенном сайте (адрес берётся из
   переменной репозитория `APP_URL`: Settings → Secrets and variables →
   Actions → Variables). Это не только триггерит сбор, но и не даёт
   бесплатному Render уйти в сон между визитами, так что таймер из пункта 1
   продолжает тикать.

Изменить интервал внутреннего таймера — задать переменную окружения
`COLLECT_INTERVAL_SECONDS` в Render (0 — выключить). Изменить расписание
GitHub Actions — поправить `cron` в `.github/workflows/keep-alive.yml`.

## Смена турнира (когда кубок заканчивается и начинается следующий)

Приложение само определяет активный турнир через mixer-cup (`activeTournament`
плюс список турниров) и **перепроверяет его раз в 10 минут** — отдельный кубок
на сайте не «залипает» после переключения. Ручных действий в норме не требуется,
но полезно знать:

- **Пауза между кубками.** Пока прошлый уже завершён, а следующий ещё в статусе
  `REDUCTION`, mixer-cup не отдаёт активный турнир вовсе. В этом случае сайт
  продолжает показывать последний известный кубок, а не «все кубки сразу».
  Интервалы настраиваются: `TOURNAMENT_CACHE_TTL_SECONDS` (по умолчанию 600) и
  `TOURNAMENT_RETRY_SECONDS` (60).
- **Название нового кубка.** Нумерация mixer-cup своя и с брендированной не
  совпадает (кубок 28 у них называется «Mixer Cup #5»). Отображаемые названия
  задаются в `MIXER_TOURNAMENT_LABELS` в [app.py](app.py) и переопределяются
  переменной окружения: `MIXER_TOURNAMENT_LABELS="29:PARI Mixer Cup #4"`.
  Свой лейбл всегда в приоритете, живое имя из API — только запасной вариант.
- **league_id.** Если новый кубок получил новую лигу в доте, её нужно добавить
  **последней** в `LEAGUE_ID` (`19924,<новая>`); прошлые id остаются в списке,
  чтобы их матчи можно было заново скачать из Steam после сброса диска.
  Проверить лигу матча: `GET https://api.opendota.com/api/matches/{match_id}`,
  поле `leagueid`. Если этого не сделать, сайт не сломается, но матчи придётся
  тянуть из OpenDota по одному — медленно и с риском упереться в rate-limit.
- **Прошлые кубки остаются в истории.** Матчи, составы и пулы героев видны на
  страницах игроков, с разделителями по турнирам; клик по команде из такого
  матча открывает состав и игры именно того кубка (см. `?tournament=` ниже).
- **Замены прошлых кубков намеренно удаляются** — на сайте показывается только
  история замен активного кубка. Данные невосстановимы (mixer-cup сам чистит
  свою историю), так что если они нужны, сохраните `backup.json` из ветки
  `data-backup` до переключения.

## Адреса страниц

У каждого турнира и каждой страницы свой адрес, так что ссылку можно скинуть
в чат и она откроется сразу на нужном месте:

| Адрес | Что показывает |
|---|---|
| `/` | текущий турнир (всегда актуальный, что бы ни было активно) |
| `/mixercup2` | конкретный турнир: слева его команды |
| `/mixercup2/team/10186631` | команда — состав и игры **того** турнира |
| `/mixercup2/team/10186631/analysis` | сразу вкладка аналитики (ещё есть `/subs`) |
| `/mixercup2/players` | лидерборд турнира |
| `/mixercup2/subs` | замены турнира |
| `/player/1840524315` | игрок: сквозная история по всем турнирам |
| `/match/8919550204` | матч: составы, KDA и драфт |

Слаг берётся из номера в названии турнира (`MIXER_TOURNAMENT_LABELS`): кубок
с названием «PARI Mixer Cup #4» автоматически получит адрес `/mixercup4`.
Турнир без своего названия доступен как `/cup<id>`. Переопределить —
`MIXER_TOURNAMENT_SLUGS="29:kubok4"`.

Страницы рисует браузер (переходы мгновенные, без перезагрузки), но адрес
меняется по-настоящему через History API: работают «назад/вперёд», обновление
страницы и открытие ссылки в новой вкладке. Сервер отвечает на все эти адреса
одной и той же оболочкой — см. `spa_route` в [app.py](app.py).

В шапке — переключатель турниров; он появляется, когда турниров больше одного,
и кнопки «Игроки», «Статистика», «Замены» остаются внутри выбранного турнира.

## Платный доступ только к текущему турниру

По умолчанию (`ACCESS_KEYS` задан) по ключу закрыт весь сайт. Переменная
`PUBLIC_ARCHIVE=1` переключает его в другой режим: **прошедшие турниры видны
всем, текущий — только по ключу.**

Выключено по умолчанию сознательно: включение посреди турнира раздаст ровно то,
за что люди заплатили, так что это должно быть отдельным решением — ставить
`PUBLIC_ARCHIVE=1` в начале нового кубка.

Что в этом режиме доступно без ключа:

- страницы и API прошедших кубков целиком — команды, составы, драфты,
  аналитика, статистика героев, лидерборд;
- страница игрока, но **без секций текущего турнира**: его матчи за этот кубок
  скрыты, и вместо названия команды написано «Команда текущего турнира — по
  ключу» (текущий состав — самое ценное, что здесь есть);
- страница матча прошедшего кубка; матч текущего отдаёт 403.

**Пулы героев закрыты всегда**, даже на прошедших кубках: и блок «Пул героев» у
игрока, и списки героев в карточках состава, и колонка «Топ героев» в
лидерборде, и блок «Играют почти всегда одни и те же». Отдельные матчи при этом
остаются публичными сознательно — каждый из них есть на Dotabuff, куда ведёт
ссылка с нашей же страницы матча, так что прятать «кто на ком играл в одной
игре» было бы бессмысленно. Сложить эти игры в пул с числом матчей и винрейтом
— это и есть работа, которую делает сайт. Агрегаты по героям без привязки к
игрокам (винрейты героев, частота банов) остаются открытыми.

Всё, что относится к активному кубку, отвечает `403` с телом
`{"error": "locked"}`, а фронтенд показывает панель с условиями доступа. Именно
403, а не 401: на 401 фронтенд уводит на `/login`, что для посетителя, у
которого ключа никогда не было, было бы неверно. Замены прошлых кубков в базе
не хранятся вообще (см. выше), поэтому раздел «Замены» целиком относится к
активному турниру.

Если активный турнир определить не удалось (mixer-cup недоступен), без ключа не
отдаётся **ничего** свежего — иначе каждый сбой их API открывал бы текущий
кубок бесплатно.

> **Обязательно задайте `OPS_TOKEN`,** включая этот режим. `/api/backup`
> отдаёт все команды, игроков, драфты и хеши ключей доступа одним файлом; это
> было безопасно лишь потому, что весь сайт требовал ключ. При
> `PUBLIC_ARCHIVE=1` операционные эндпоинты без токена отвечают `403` — то
> есть сбор данных и бэкапы по расписанию перестанут работать, пока токен не
> задан и в окружении сервиса, и в секретах GitHub. Сессия обычного
> пользователя эти эндпоинты **не** открывает: платящий клиент не оператор.

Заодно стоит задать `AUTH_SECRET` явным значением — по умолчанию он выводится
из самого набора ключей, и им же подписываются сессии.

## CLI (без браузера)

Тот же сбор данных и текстовая сводка доступны без веб-интерфейса:

```bash
python -m pari_mixer_scraper.collect --league-id 19924 --db tournament.db
python -m pari_mixer_scraper.report --db tournament.db
```

## Схема базы данных

- `heroes(hero_id, name, localized_name)`
- `teams(team_id, name)`
- `players(account_id, name, team_id)`
- `matches(match_id, league_id, start_time, duration, radiant_team_id, dire_team_id, radiant_win)`
- `match_players(match_id, account_id, hero_id, team_id, is_radiant, kills, deaths, assists)`

- `player_notes(note_id, account_id, author, text, author_key_hash, created_at)`

`match_players` — основная таблица для вопроса "какой игрок на каком герое
играл"; на ней строятся и веб-эндпоинты, и `report.py`.

`player_notes` — единственные данные, которые здесь пишутся, а не скачиваются:
всё остальное можно собрать заново из Steam, mixer-cup и OpenDota, а заметку
нельзя. Поэтому она попадает в `/api/backup`, восстанавливается из него и
переносится сборщиком в новую базу перед подменой (`_carry_over_notes`) — иначе
заметка, написанная во время сбора, пропала бы вместе со старым файлом.
Заметки, созданные после последнего коммита бэкапа, при сбросе диска всё же
теряются: интервал задаётся расписанием в `.github/workflows/keep-alive.yml`.

## API веб-приложения

- `GET /api/tournaments` — турниры с адресами и пометкой активного.
- `GET /api/teams` — список команд с числом игроков. `?tournament=<id>` —
  команды прошедшего кубка (под их тогдашними названиями); без него активный.
  Тот же параметр понимают `/api/players`, `/api/tournament/heroes` и
  `/api/substitutions`.
- `GET /api/teams/<team_id>` — игроки команды и герои, на которых каждый играл.
  Необязательный `?tournament=<mixer_tournament_id>` открывает то воплощение
  команды, которое играло в указанном кубке: свой состав, свои игры и своё
  тогдашнее название. Нужен потому, что mixer-cup переиспользует одни и те же
  зарегистрированные в доте команды из кубка в кубок. Тот же параметр
  понимает `/api/teams/<team_id>/analysis`.
- `GET/POST /api/players/<account_id>/notes`, `DELETE .../notes/<note_id>` —
  заметки об игроке. Общие для всех, у кого есть ключ: каждая подписана ником,
  который автор ввёл сам (аккаунтов нет, есть общие ключи). Читать и писать
  можно только с ключом, удалять — только свои: заметка помнит HMAC ключа,
  которым была создана. Лимиты: 2000 символов текста, 40 ника, 200 заметок на
  игрока.
- `POST /api/collect` — запускает сбор данных в фоновом потоке (409, если уже запущен).
- `GET /api/collect/status` — статус текущего/последнего сбора и лог.

## Если league_id не подходит

- Проверить название лиги: `GET https://api.opendota.com/api/leagues/{league_id}`.
- Список всех лиг для поиска по имени: `GET https://api.opendota.com/api/leagues`.
- `leagueid` конкретного матча: `GET https://api.opendota.com/api/matches/{match_id}`.

## Ограничения

- Игроки, скрывшие профиль (анонимный `account_id`), не сопоставляются между
  матчами — такие записи пропускаются с предупреждением в логе.
- OpenDota, бесплатный тариф: 60 запросов/мин, 50k/месяц — клиент сам
  выдерживает паузы и повторяет запрос при 429.
- Steam Web API также ограничен по частоте запросов; клиент выдерживает
  паузу между запросами и делает retry при 429.
