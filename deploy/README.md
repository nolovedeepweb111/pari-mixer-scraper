# Перенос на свой сервер

Render не открывается из России, а его бесплатный тариф вдобавок обнуляет диск
при каждом деплое и засыпает через 15 минут простоя. Свой VPS снимает всё это
разом: сайт доступен аудитории, база живёт постоянно (матчи перестают теряться
из-за окна Steam), процесс не засыпает — и таймер сбора наконец тикает
по-настоящему, а не раз в несколько часов.

## Что понадобится

- **VPS в России**, самый дешёвый: 1 ядро, 1 ГБ памяти, 10 ГБ диска. Timeweb,
  Selectel, Beget — порядка 200–300 ₽/мес. Ubuntu 24.04.
- **Домен**, направленный A-записью на IP сервера. Без него не выпустить
  сертификат, а по HTTP сессионная кука с ключом доступа ходит открытым
  текстом — для платного сайта так нельзя.

Аккаунты и оплату делаете вы: агент не регистрирует аккаунты и не работает с
вашими доступами к серверу.

## Установка

Все команды — от root на чистом сервере.

```
apt-get update && apt-get install -y git
git clone https://github.com/nolovedeepweb111/pari-mixer-scraper.git /tmp/pms
bash /tmp/pms/deploy/install.sh
```

Скрипт поставит зависимости, заведёт пользователя `pari`, развернёт код в
`/opt/pari-mixer-scraper`, соберёт виртуальное окружение, создаст
`/etc/pari-mixer/env` из шаблона и включит сервис.

Дальше впишите секреты:

```
nano /etc/pari-mixer/env
```

Обязательные: `APP_DOMAIN`, `STEAM_API_KEY`, `ACCESS_KEYS`, `AUTH_SECRET`,
`OPS_TOKEN`. Значения `AUTH_SECRET` и `OPS_TOKEN` берите те же, что стояли в
Render, иначе разлогинятся все выданные ключи и перестанут работать бэкапы.

Затем перезапустите, настройте nginx на домен и выпустите сертификат:

```
bash /tmp/pms/deploy/install.sh
```

```
certbot --nginx -d ваш.домен
```

## Обновление

Установщик кладёт на сервер команду `pms-update`, поэтому выкат свежего
master — это:

```
pms-update
```

Она забирает код во временный каталог и запускает оттуда `install.sh`
(идемпотентный: обновит код и зависимости, перезапустит сервис, секреты и
конфиг nginx не тронет). Запускать `install.sh` прямо из
`/opt/pari-mixer-scraper` нельзя: он делает своему же каталогу
`git reset --hard` во время работы, то есть переписывает файл, из которого в
этот момент читается сам.

Если `pms-update` ещё не установлена (сервер ставили до её появления), один
раз выполните длинный вариант — он её и положит:

```
rm -rf /tmp/pms && git clone https://github.com/nolovedeepweb111/pari-mixer-scraper.git /tmp/pms && bash /tmp/pms/deploy/install.sh
```

Проверка:

```
journalctl -u pari-mixer -f
```

При первом старте база пуста, поэтому через 45 секунд сам запустится сбор: он
восстановит команды, игроков, замены, заметки, драфты и матчи из ветки
`data-backup`, а свежие матчи доберёт из Steam. Занимает пару минут.

## После переезда

1. В GitHub → Settings → Secrets and variables → Actions → Variables поменяйте
   `APP_URL` на новый адрес, иначе бэкапы продолжат сниматься со старого сайта.
2. Убедитесь, что в ветке `data-backup` появился свежий коммит.
3. Сервис на Render можно удалить — но лучше после того, как новый проработает
   день и в бэкапе появится секция `matches`.

## Обновление кода

```
bash /tmp/pms/deploy/install.sh
```

Скрипт подтянет свежий `master`, обновит зависимости и перезапустит сервис.
База в `/var/lib/pari-mixer` не трогается.

## Почему один воркер

В `pari-mixer.service` стоит `--workers 1`, и это не тюнинг. Привязки ключей к
устройствам, статус сбора и кэш активного турнира лежат в памяти процесса: со
вторым воркером часть запросов видела бы другую картину, а ограничение «один
ключ — два устройства» перестало бы работать. Параллелизм обеспечивают потоки,
которые эту память делят.
